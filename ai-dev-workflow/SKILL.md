# AI 开发工作流

核心不是把流程走满，而是每一步只做当前必要的动作。模型变强之后，固定的重流程会变成噪声；
工作流要跟着模型迭代定期做减法。

## 第一步：先判断规模

| 规模 | 做什么 |
|---|---|
| 改一行 / 改个字段 / 修个校验 | 直接改 + 自测。**不进入下面的流程** |
| 单模块的小需求 | 对齐 → 实现 → 自测 → 自查 |
| 跨模块 / 有架构决策 | 走完整五步 |

步骤是给不确定性准备的，不是给所有任务准备的。

## 五步流程

### 1. 对齐：把没说出口的假设问出来

喂给 Agent 真实材料：PRD、会议纪要、聊天记录、用户反馈，再结合团队 Wiki 和现有代码理解。
这些材料通常互相不一致——PRD 没更新、会上补了限制、聊天里又调了优先级。

用连续追问的方式，把会影响实现的目标、边界和取舍问清楚。**停止条件：剩下的问题已经不会
显著改变实现方向和验收结果。** 不要求把实现细节提前规划完，否则对齐本身会变成一套重流程。

### 2. 沉淀：让后续 Agent 共享同一份上下文

结论写进 `Spec` 或 `CONTEXT.md`，只记四样：

- 这次要解决什么问题
- 范围（做什么 / 不做什么）
- 关键决策及理由
- 验收标准

好处是负责实现和审查的 Agent 不必重读全部对话。

### 3. 实现：按复杂度决定怎么拆

- 简单需求：直接实现。
- 复杂需求：拆成边界清楚、可独立验收的 Issue。
- **只有能独立推进的部分才交给 subagent**，各自在独立 worktree 并行；主 Agent 负责集成。

不要为了并行而并行——集成成本往往比省下的时间高。

### 4. 自测：给 Agent 一个能跑通的端到端环境

这是整条链路里投入产出最高的一环。四件事：

1. **熟悉环境**：一键起测试环境、造测试数据、明确版本/账号/权限、能清理和重置。
2. **能操作业务**：通过浏览器、API 或 CLI 走真实业务流程。
3. **能查证据**：只读数据库确认落库，日志和 Trace 解释失败。
4. **固化流程**：稳定操作写脚本，入口和排障方法写成 Skill，最后可以整合成一个统一测试 CLI。

**铁律：工具提供证据，不定义正确答案。** 预期结果必须来自业务契约，不能让 Agent 看到系统
返回什么就认为什么是对的。复杂业务下，系统完全可能返回一个看似合理、实际不符合需求的结果。

产品本身是 Agent 时，除了流程跑通，还要评估答案质量。

### 5. 审查：把精力放在高风险处

- 先看 Agent 给出的验收标准，再对照端到端测试结果。**不只看通过率，看测试是否验证了这次
  真正关心的事情。**
- 沿业务路径看实现，重点检查：权限、状态变化、并发、重试、数据一致性、迁移与回滚。
  模式稳定的 CRUD 可以少看甚至不看。
- 新增的抽象和机制，单独再过一遍奥卡姆剃刀。
- **保持 MR 足够小**，这样才能在不逐行读代码的前提下做出判断。

## 思维快捷键

模型训练时见过大量成熟方法论，不需要手写几百行 Workflow，直接报方法论名字即可。
这些短句的价值在于指定「用哪种方式思考」，而不是「按哪几步走」。

| 方法 | 什么时候用 | 可以直接说的话 |
|---|---|---|
| **第一性原理** | 怀疑题目本身问错了 | `不要基于「加缓存」这个既定方案继续设计。从第一性原理分析它为什么慢，以及最小必要的解决方案。` |
| **对抗性审查** | 方案评审、Code Review | `对这个方案做一次对抗性审查，优先寻找能推翻核心假设的反例。` |
| **消融实验** | 一次做了多个优化，想确认收益来源 | `给这几个优化设计消融实验，判断真正的收益来自哪里。` |
| **奥卡姆剃刀** | 设计里堆了太多机制 | `用奥卡姆剃刀重新审查这个设计，在满足需求的前提下删除所有非必要机制。` |
| **高内聚低耦合** | 单个文件/服务过大 | `按高内聚、低耦合原则审查 XXService 的职责边界，不要为了拆而拆。` |

一句话串起来就是五种认知动作：

> 重新定义问题 → 攻击假设 → 验证贡献 → 删除复杂度 → 整理边界

不要写成「第一步分析需求，第二步检查假设……」这种固定剧本。

## 反模式

- 需求没说清就开写，然后用大量代码掩盖理解偏差。
- 给一次改字段也套完整五步流程，token 全花在流程上。
- 用「测试通过率」代替「验收标准是否被验证」。
- 为了解决一个局部问题，引入新的分布式故障点（锁、缓存、消息队列）。
- 只给 Agent 加约束，不定减；模型升级后旧约束没有清理。
- 代码和测试互相自洽就认为没问题——它们可能一起误解了需求。
